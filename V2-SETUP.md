# КТО Я? v2 — тестовая ветка

## Что изменено
- Универсальный вход, цели (личность, профессия, бизнес, отношения, блог), профиль с семью системами, тематический синтез и 13-недельные маршруты.
- Сохранены старые инструменты креатора: вкладка «Мой блог» и экран «Код креатора». UNIQ — ссылка из прежней воронки.
- Подписки нет. Разовые пакеты: 149 / 399 / 449 Stars (текущие цены, не окончательная ценовая проверка).
- Сюцай — базовая реализация чисел сознания и миссии; требуется уточнить школу трактовок. Матрица — существующая версия пяти точек. Совпадение интерпретаций не научная оценка.

## Предпросмотр
Ветка kto-ya-v2 не меняет main. GitHub Pages, если публикуется main, продолжит показывать старый продукт. Для отдельного теста развернуть эту ветку в отдельный Pages/preview проект или локально запустить статический HTTP-сервер из корня. Не переключать рабочую публикацию до проверки сценариев.

## Аналитика
1. В Cloudflare создать D1 базу; выполнить SQL из worker/metrics.sql.
2. Привязать к Worker/worker.js D1 как METRICS.
3. Создать секрет ADMIN_METRICS_KEY (случайная длинная строка, не хранить в GitHub).
4. Установить ALLOWED_ORIGIN = точный origin приложения, например https://francez89.github.io. Развернуть Worker; сохранить его HTTPS адрес.
5. В js/config.js указать analyticsEndpoint = адрес Worker + /analytics.
6. Открыть admin.html на том же origin, указать адрес Worker и секрет. Доступ к данным только после серверной проверки ключа. Не сохранять секрет в публичном коде.
7. Проверить согласие в приложении, затем пройти тестовый путь. Данные появятся в админке после отправки событий. Проверить, что без согласия события не отправляются.

События: старт сессии, экран, длительность, цель, профиль, завершение архетипов, действия, интерес к покупке, переход в UNIQ, выполнение шага. Источники — utm_source, utm_campaign или Telegram start_param, закреплённые при первом согласии. Анонимный ID относится к браузеру/устройству, не к человеку на всех устройствах. Платежи считаются отдельно по подтверждённому webhook. Время приблизительное. Воронка — число уникальных ID на каждом событии, не строгая последовательная когорта. При росте трафика добавить ограничения частоты запросов и политику хранения/удаления; endpoint сбора публичный и события можно подделать, не использовать их как финансовую отчётность.

Не отправлять в METRICS имена, дату рождения, город, тексты, ответы или Telegram ID. Встроенный старый модуль напоминаний может отправлять дату рождения в отдельный Worker при его активации; для него нужна отдельная прозрачная политика.

## Платежи
Пока paymentsEnabled=false, openAll=false: показываются предложения, по кнопке — контакт автора. Реальные платежи не включены.
Для запуска: настроить KV DB, BOT_TOKEN, WEBHOOK_SECRET, Telegram webhook /tg и цены STARS_CODE, STARS_STRAT, STARS_PRO. Указать Worker в analyticsEndpoint (или других существующих endpoint), проверить /invoice и /me. Только потом paymentsEnabled=true. Тестировать успешную оплату, повторный webhook, восстановление покупки на другом устройстве. Публичный клиентский код содержит тексты платных разделов: замок мягкий. Для надёжной защиты выдавать платный контент сервером. Не включать подписку.
UNIQ: сейчас используется ранее указанная ссылка https://t.me/uniqvideobot?start=stories. Для отдельных измерений продаж добавить отдельный поддерживаемый параметр start на стороне UNIQ; пока считаются лишь исходящие переходы.

## Проверка перед публикацией
Проверить на телефоне новый пользователь → выбор цели → данные рождения → главный экран; без времени рождения; полный тест архетипов; каждая система; профиль и маршрут; переход в Мой блог, существующие инструменты, UNIQ; согласие и отказ; повторный заход; покупки после настройки. Не публиковать main без проверки.
